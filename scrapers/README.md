# Scrapers

Scrapers are written in Python. Each one downloads an official source file, saves the raw file unchanged, and writes a versioned CSV. They need Python 3 and the packages in `requirements.txt` (install with `pip install -r scrapers/requirements.txt`). Run them from the project folder.

| Script | What it does |
|---|---|
| `commonwealth_debt.py [year]` | Downloads Appendix B and Part 1 of the Final Budget Outcome (Word files) from archive.budget.gov.au, reads Tables B.4 (net debt) and B.5 (total AGS on issue) in code, and writes `metrics/commonwealth-debt/data.csv`. The year is the folder name in the web address and defaults to `2025-26`. Raw files and `sources/manifest.json` go in `metrics/commonwealth-debt/sources/`. |
| `cpi_june.py` | Downloads the quarterly Consumer Price Index from the ABS Data API, keeps the June quarters from 1971, and writes `shared/cpi_june.csv`. The raw response and `shared/sources/manifest.json` go in `shared/sources/`. |
| `unemployment_rate.py` | Downloads the monthly unemployment rate (series `M13.3.1599.20.AUS.M`) from the ABS Data API, rounds each value to the ABS's own number of decimal places (half up), finds the current Labour Force Table 1 spreadsheet link on the ABS "latest release" page, and refuses to write unless spreadsheet series A84423050A agrees for every month and ends on the same month. Writes `metrics/unemployment-rate/data.csv`; the raw API response and spreadsheet and `sources/manifest.json` go in `metrics/unemployment-rate/sources/`. The reading and checking helpers are in `abs_series.py`, which any later ABS series can reuse. |
| `inflation.py` | Downloads three series into `metrics/inflation/`. (1) Year-ended headline inflation, quarterly, from the Reserve Bank's table G1 (series `GCPIAGYP`, from 1950-Q1), stored as published and checked quarter by quarter against the year-ended change worked out in code from the ABS quarterly CPI index (Data API `CPI 1.10001.10.50.Q`). (2) The year-ended trimmed mean, quarterly, seasonally adjusted (`CPI_Q 3.999902.20.50.Q`), checked against G1 series `GCPIOCPMTMYP`: from 2002-Q1 every quarter must agree; before 2002 the two differ in some quarters, which are printed and counted but do not stop the scraper. (3) Year-ended headline inflation from the complete monthly CPI (`CPI 3.10001.10.50.M`), checked month by month against ABS Table 1 (`640101.xlsx`, whose address is read from the CPI "latest release" page; the column is found by its header text and must be unique). The ABS leaves the DECIMALS cell empty for these series, so a figure is accepted only if it already has at most one decimal place; a figure with more is refused, never rounded. Raw downloads and `sources/manifest.json` go in `metrics/inflation/sources/`. |
| `wages_and_prices.py` | Writes `metrics/wages-and-prices/` with two series. (1) Year-ended wage growth, quarterly, from the ABS Data API (`WPI 3.THRPEB.7.TOT.20.AUS.Q`: Wage Price Index, total hourly rates of pay excluding bonuses, private and public, all industries, seasonally adjusted). The response has no DECIMALS column and starts with blank quarters (1997-Q3 to 1998-Q2); blanks before the first figure are skipped and a blank after it is refused. A figure is accepted only if it already has at most one decimal place. Every quarter is checked against Table 1 (`634501.xlsx`, address read from the Wage Price Index "latest release" page), series ID A83895396W, and the two must cover the same quarters and end on the same one. (2) Price growth, copied from the `headline_quarterly` rows of `metrics/inflation/data.csv` from the first wage quarter on (nothing is downloaded; the path and checksum of the inflation file are recorded in the manifest). It refuses if the inflation file is missing, has a gap, has no figure for the first wage quarter or ends before the latest wage quarter. The checker (`copy_of`) enforces that the two stay equal. |
| `rogs.py` | Not run by itself: the reusable loader for the Productivity Commission's Report on Government Services. `discover` finds the newest year's data-downloads page and the one link whose file name has the section slug (falling back to the previous year, and saying so, if the newest page lacks it; refusing on none or two); `parse_dataset` and `select` read the CSV and pick rows by exact matches on named columns, refusing unless there is exactly one row per year; `read_workbook` and `cross_check` read the same figures from the Excel table (sheet by table number, rows by their labels with footnote marks removed) and refuse unless every selected figure agrees; `merge_history` keeps stored years that the new edition no longer carries and records the edition each year came from. Cell codes (`..`, `na`, `np`, nil) stay codes. `read_workbook` reads both layouts the Commission uses (the year as the figure row's own label, as in housing, or a year row above its figures, as in hospitals), can add the row's Unit to the path (`unit_in_path`, for a count and a per cent with the same label), reads one of two side-by-side column sets by its heading (`group`, for the 50th and 90th percentile) and reads sheets whose declared size is wrong (some Commission workbooks declare each sheet as the single cell A1). |
| `social_housing.py` | Writes `metrics/social-housing/`: dwellings at 30 June from RoGS table 18A.3 (public housing, state owned and managed Indigenous housing, community housing in tenancy units, Indigenous community housing; 2016 onwards) checked figure by figure against the Commission's Excel tables, and the ABS estimated resident population at 30 June from the ABS Data API (`ERP_Q 1.3.TOT.<region>.Q`, region names confirmed from the labelled response) checked against the ABS spreadsheet found by its column headers. Stores codes as codes; keeps older years when a new edition drops them (`rogs-editions` in the manifest). The total and the rate per 1,000 are worked out by the site, not stored. |
| `hospital_waits.py` | Writes `metrics/hospital-waits/`: four series for the financial years 2015-16 onwards from RoGS section 12 (public hospitals), read from the Commission's CSV by exact column matches and checked figure by figure against its Excel tables: `ed_seen_on_time` (table 12A.13, patients seen on time, all triage categories excluding unknown, whole per cents), `ed_within_4_hours` (12A.18, stay of four hours or less, one decimal), `surgery_median_days` and `surgery_90th_days` (12A.23, all public hospitals, all procedures, 50th and 90th percentile, days). Table 12A.24 is never used: it has two rows per year with different coverage. A year is dated 30 June of its second year and keeps the Commission's label ("2024-25") as the period; the number of decimal places is checked, so the page never shows a decimal the source lacks. Stores codes as codes; keeps older years when a new edition drops them (`rogs-editions` in the manifest). Downloads everything it needs itself. |
| `homelessness.py` | Writes `metrics/homelessness/`: from RoGS section 19 (homelessness services), read with `rogs.py` from the Commission's CSV by exact column matches and checked figure by figure against its Excel tables. Census series (table 19A.2, total homeless, 2011, 2016, 2021): `census_homeless_rate` (per 10,000 people, one decimal) and `census_homeless_number`, each dated its Census night from the map `CENSUS_NIGHT` in the script (9 August 2011, 9 August 2016, 10 August 2021; a Census year not in the map, such as 2026, stops the update until its date is added; the Censuses must be five years apart). Service series (financial years from 2020-21, dated 30 June of the second year): `clients` and `unmet_accommodation_pct` (table 19A.10, Measure "Unmet need") and `unassisted_accommodation_daily`, `unassisted_other_daily` and `unassisted_no_need_daily` (table 19A.11, average daily unassisted requests, unit `per_day`). The total of the three daily series is worked out by the site. The Commission prints a true zero as a plain 0 in the one-decimal table 19A.11; that is accepted and stored as published, and any other wrong number of decimal places is refused. Stores codes as codes; keeps older periods when a new edition drops them (`rogs-editions` in the manifest). Downloads everything it needs itself. |
| `rents.py` | Writes `metrics/rents/`. (1) The CPI rents index, eight capitals, original, quarterly, from the ABS Data API (`CPI 1.115522.10.50.Q`), from 1972-Q3, stored exactly as given (at most two decimal places, never rounded) and checked quarter by quarter against Table 18 (`6401018.xlsx`, series A2331876F). (2) The published twelve-month change in rents from the monthly CPI, Australia (`CPI 3.115522.10.50.M`, from July 2023), checked month by month against Table 3 (`640103.xlsx`, series A130390095C). (3) The same for each capital city (`CPI 3.115522.10.1+2+3+4+5+6+7+8.M`), stored with the state or territory as the jurisdiction. The region names are confirmed by asking the same address for labels (1 Sydney ... 8 Canberra, or it refuses) and each city is checked against Table 11 (`6401011.xlsx`), whose two Original columns per city must agree with each other and with the API. Every period must be in both sources, every period that is must agree and the latest must match. The quarterly twelve-month change is not stored: the site works it out from the index (`derive` in `metric.yml`); the scraper only prints the latest worked-out figure for the checking notes. It downloads everything it needs itself and depends on no other scraper. |
| `run_all.py --status <file>` | Runs every scraper in turn (the list is at the top of the file; the inflation scraper runs before the wages one, and if it fails the wages one is skipped and reported as failed), carries on if one fails, and writes a small JSON file saying how each went, with the last 30 lines it printed. It exits 0 even when a scraper failed, because the report carries the failure. |
| `report.py --before <folder> --after <folder> --status <file> --out <file.md>` | Compares the `metrics/` and `shared/` folders of two copies of the project and writes the weekly "what changed" report (see below). Optional: `--changed-flag <file>` writes true or false, `--today YYYY-MM-DD` is for testing. It does not use git. |

The download scrapers check everything first and write nothing if a check fails. They print `ERROR:` and exit with code 1. The debt scraper stops if a table is not found, a year is missing or repeated, a value cannot be read (it understands every kind of minus sign and ignores footnote markers), the two tables cover different years, a value is outside a sensible range, the row count falls, or the latest year does not match the Part 1 overview table. The price scraper stops if a June quarter is missing. The inflation scraper stops on a non-200 answer, an unexpected code, a repeated or missing quarter or month, an unreadable value, a figure with more than one decimal place, any cross-check failing (headline against the ABS index in any quarter; trimmed mean against G1 in any quarter from 2002; monthly against Table 1 in any month; the latest period differing in any of the three), a missing or duplicated column, or fewer rows than before in any series. The unemployment scraper stops on a non-200 answer, a missing column, any unexpected dimension code, a repeated or missing month, an unreadable value, the spreadsheet disagreeing with the API about any month or about the latest month, or fewer rows than before.

The manifest records, for each saved file, the web address, the date retrieved (UTC), a SHA-256 checksum and the size in bytes.

## The weekly update and its report

`.github/workflows/weekly-update.yml` copies `metrics/` and `shared/` aside, runs `run_all.py`, then runs `report.py` to compare the before and after copies. The report has these sections, each saying "None" when empty: new data points, revised history (old and new value and the difference), removed data points (this should never happen and is flagged loudly), sources (whether each downloaded file changed, and any scraper that failed with what it printed), shared files (the price index; a change to it changes every inflation-adjusted figure), targets due within 90 days, and what to do.

Each revised figure that is over its series' allowed revision (the `revision` setting in `metric.yml`, see `metrics/README.md`) starts with **LARGE:**. `report.py` reads that setting with its own small YAML reader, which understands only the one-line form `revision: {max_abs: 500, max_pct: 1, pct_floor: 5000}` under each series. If a series' setting is written any other way, the report says it could not read it and marks nothing for that series; the validator still enforces it. The rule used is the same as the validator's (`scripts/validate.mjs`).

If anything changed, the job runs `npm run validate`, then `npm run accept-data` and `npm run build`, and opens a pull request on a branch named `data-update/<date>` with the report as its description. The owner reads the report, checks the figures against the source, and merges, or closes the pull request. If validation fails, nothing is committed and an issue called "Weekly update blocked: validation failed" is opened or updated; when the cause is a large revision to a past figure, the issue says so. The owner then accepts a genuine revision on the PC with `npm run accept-data -- --accept-revisions`, and commits and pushes the result. If nothing changed but a source could not be read, an issue called "Weekly update: a source could not be read" is opened or updated. If nothing changed and nothing failed, the job finishes quietly. Nothing is pushed to the main branch directly.

The job's download dates (the "retrieved" lines in the manifests) change every week even when the figures do not. The report ignores them when deciding whether anything changed, so an ordinary quiet week makes no pull request.

One setting is needed once, on GitHub: Settings, Actions, General, Workflow permissions, and tick "Allow GitHub Actions to create and approve pull requests".

Tests: `python3 scrapers/tests/test_report.py` (the report and `run_all.py`, no network), `python3 scrapers/tests/test_commonwealth_debt.py` `python3 scrapers/tests/test_unemployment_rate.py` and `python3 scrapers/tests/test_inflation.py` and `python3 scrapers/tests/test_wages_and_prices.py` and `python3 scrapers/tests/test_rents.py` and `python3 scrapers/tests/test_rogs.py` and `python3 scrapers/tests/test_social_housing.py` and `python3 scrapers/tests/test_hospital_waits.py` and `python3 scrapers/tests/test_homelessness.py`. `abs_series.py` also finds a spreadsheet column whose header only has to contain some text (`description_contains`), finds every column with a header across all the Data sheets (`find_series_ids_by_header`), reads quarterly periods (`freq="Q"`) and, when the ABS leaves DECIMALS empty, takes a `blank_decimals` setting.

The debt scraper's tests run without a network. They read a saved copy of the 2024-25 Appendix B file and compare it with the figures a language model once read from the PDF (both in `scrapers/tests/fixtures/`).

Every scraper must follow the nine data rules from the build plan, in plain words:

1. Never type a figure. Every number comes from a file the scraper downloaded. The metric's definition file records the web address, the table, the date retrieved and a checksum of the file.
2. One folder per metric, holding `metric.yml`, `data.csv`, `sources/` (raw files as downloaded) and `NOTES.md`.
3. Use the long CSV shape (`date, period, series, jurisdiction, value, unit, status`). Status is `actual`, `estimate` or `forecast`. Dates are real dates, and the source's own period label goes in `period`.
4. Check the data before publishing, and refuse to publish if a check fails: no missing years inside a series; values inside a stated sensible range; the latest value matches a second official statement of the same figure where one exists; and the row count never falls between runs.
5. Work out derived figures (inflation-adjusted dollars, per person, straight-line pace) in code, label them as derived, and print the formula on the page.
6. Keep revisions. When a source revises its history, the old CSV stays in version history and the page notes that figures were revised and when.
7. Disclose conflicts. If two official sources disagree, show both and say so.
8. A person checks every new page before it is first published. They check the latest value and five other points against the source, and initial the metric's `NOTES.md`. A page without that check stays in draft.
9. A reading model is not a parser. Read the source file in code (the Excel or CSV version where one exists), then have a person spot-check it. Reading a PDF with a language model is only good enough for a prototype.
